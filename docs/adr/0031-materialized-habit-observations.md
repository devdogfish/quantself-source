# Materialize Habit Occurrences as source observations

For #143 (PRD #142), Habit Occurrences are PostgreSQL source facts, consistent with ADR 0003. Each Owner/Habit/Halifax-date has at most one row. A minute worker materializes only today's eligible tracked build Habits, with a lazy read backup, using a bulk insert that never updates existing rows. Rows retain the definition SHA used at creation. Break, pending, paused, pre-start and off-schedule Habits create no rows. Open becomes missed only after America/Halifax midnight, including DST.

Downtime leaves absent dates unknown: never backfill missed rows by applying today's definition to historical days. Explicit past done/minimum corrections can create one eligible row using the current definition SHA, making that provenance explicit. Existing observations remain correctable even when a Habit is paused or removed. Future skips create only the requested eligible occurrence; future reads never materialize future dates. Retrospective skips are rejected. Definition edits never rewrite existing observations.

Status/note commands atomically compare revision and before values, update the row, and store a Client-scoped commandId receipt in one serializable transaction. Identical retries return the original result; a changed payload conflicts. Receipts are durable, separate from the disposable projection. The Web Client serializes dependent commands per occurrence, keeps later intent over older acknowledgements, and retains unchanged commands for uncertain retries. Rejections remove only that occurrence's dependent intent; unrelated work survives.
