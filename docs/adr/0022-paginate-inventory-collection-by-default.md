# Paginate the Inventory collection by default

The Inventory collection API uses stable cursor pagination by default, returning 24 records plus a total count and next cursor. The Web Client progressively loads the next page before the owner reaches the visible end, while clients that intentionally need the complete collection may explicitly request `limit=all`; this keeps ordinary browsing bounded without removing bulk access for capable clients. Every search and filter is applied server-side before pagination, and changing one invalidates loaded batches and cursors. Filters remain URL-backed, while loaded batches and exact scroll position live in browser history or session state so returning from Item detail restores the prior Browse view without encoding cursors in the URL.
