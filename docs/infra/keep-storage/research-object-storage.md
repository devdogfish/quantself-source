# Offsite object storage for Quantself backups

Research checked **2026-11-13**. Rates USD, before tax; public list prices only. Scope: encrypted nightly copies of PostgreSQL dumps plus original attachments. Measured source-side backup set is ~3 GB; an offsite restic repository has not been created or sized. PBS infrastructure exists in the same home, but new-VM backups are not configured/verified. Capacity scenarios below mean billable repository footprint after backup history/deduplication, not source data size. No account or resource was accessed or created.

## Recommendation

Use **restic to Backblaze B2 Canada East** for the live nightly repository: built-in client-side authenticated encryption, B2 S3-compatible endpoint, always-hot objects, no minimum file size/duration, first 10 GB free, cheap writes/reads, and B2 supports a Canada region. At 10 GB it is $0/month; modelled 25/50/100 GB totals are about **$0.10/$0.28/$0.63 per month**. B2 rates are the same across listed regions; its pricing calculator currently labels its published chart US West. Final review: use a **30-day hidden-version retention** rule and an uploader key without permanent-version deletion, then test recovery. Restic’s S3 backend hides obsolete objects; hidden versions remain billable. The one-day “keep last version” convenience setting would undermine this recovery window. [B2 pricing](https://www.backblaze.com/cloud-storage/pricing) · [B2 regions](https://www.backblaze.com/docs/en/cloud-storage-data-regions) · [restic B2 guidance](https://restic.readthedocs.io/en/stable/030_preparing_a_new_repo.html#backblaze-b2) · [B2 lifecycle](https://www.backblaze.com/docs/en/cloud-storage-lifecycle-rules)

If keeping the first 10 GB exactly free matters and a Cloudflare account is already convenient, **R2 Standard** is also sensible: 10 GB-month and generous request allowances are recurring free usage, all Internet egress is free, and billed storage is $0.015/GB-month above free. At 25/50/100 GB it is about **$0.23/$0.60/$1.35**. R2 has S3 compatibility and a documented rclone integration. R2 has bucket locks, but its residency jurisdictions currently list US, EU, and FedRAMP—not Canada. [R2 pricing](https://developers.cloudflare.com/r2/pricing/) · [R2 S3 compatibility](https://developers.cloudflare.com/r2/get-started/s3/) · [R2 with rclone](https://developers.cloudflare.com/r2/examples/rclone/) · [R2 location](https://developers.cloudflare.com/r2/reference/data-location/) · [R2 bucket locks](https://developers.cloudflare.com/r2/buckets/bucket-locks/)

AWS S3 Standard in Canada Central is a reasonable convenience choice if using the existing AWS account for SES reduces setup friction; it costs about **$0.23/month at 10 decimal GB**, then ~$0.58/$1.16/$2.33 at 25/50/100 decimal GB. B2 saves around $0.23/month at 10 GB, but provider preference, account operations, and restore testing outweigh this small difference. Don’t reuse SES sending credentials for backup. For ransomware resistance, isolate credentials and test object-lock semantics separately; a locked live restic repository may conflict with normal pruning/deletion.

OCI is an optional free-tier route, with extra account/IAM setup: Always Free-only tenancies can hold 20 GiB combined across Standard/Infrequent/Archive (50,000 API requests/month), limited to the tenancy home region. A paid-upgraded account keeps Always Free storage: 10 GB Standard, 10 GB Infrequent Access, 10 GB Archive, and 50,000 requests/month. Standard-only model below uses the 10 GB Standard allowance; beyond that it costs the published general US$ list rate, $0.0255/GB-month (not an account-specific quote). IBM’s standard Free Tier offers 5 GB for 12 months; its 25 GB Lite plan is a 30-day trial or a deprecated legacy plan, not a new recurring-free option. [OCI Always Free](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm) · [OCI general pricing FAQ](https://www.oracle.com/cloud/storage/archive-storage/faq/) · [OCI public price list](https://www.oracle.com/cloud/storage/pricing/) · [OCI S3 compatibility](https://docs.oracle.com/en-us/iaas/Content/Object/Tasks/s3compatibleapi.htm) · [IBM Free Tier FAQ](https://cloud.ibm.com/docs/cloud-object-storage?topic=cloud-object-storage-faq-provision) · [IBM plans](https://www.ibm.com/docs/en/ws-and-kc?topic=storage-cloud-object-plans)

## Monthly storage model

Assumptions: each capacity scenario is decimal GB. AWS, Azure, and Google list storage in binary GiB, so convert scenario size by × 0.9313; B2 and R2 rates use decimal GB. OCI’s public rate unit says GB but its binary/decimal basis was not verified; its estimates assume decimal GB. Constant stored amount for a 30-day month; no versioning surplus, API/restore costs, tax, or trial credits. Rounded to nearest cent. AWS standard/archive prices come from the official Canada Central price-list offer JSON, effective 2026-10-01; Azure figures from Microsoft’s Retail Prices API (`canadacentral`, LRS, current meters). AWS and Azure per-GiB rates are multiplied by 0.9313 to estimate per-decimal-GB scenarios. Rates can change. B2 states $6.95/TB/30 days and first 10 GB free; model converts the published TB rate at 1,000 GB. R2 bills whole GB-month units, so table shows stated exact capacities.

## Operations, retention, and recovery costs

- **B2:** ingress free; Class A/B/C API calls free; Class D first 2,500/day free, then $0.004/10,000. Egress free up to 3× the monthly average stored amount, then $0.01/GB. A same-size one-time full restore is within the 3× allowance only if other egress has not consumed it; e.g., from a steady 10 GB average repository, one 10 GB restore is free, while 100 GB restore incurs about $0.70 excess egress (assuming no other egress). B2’s S3 endpoint is recommended by restic due to its native-backend error handling; use an explicit 30-day hidden-version lifecycle for this design, and include old versions in billable-storage monitoring. [B2 transaction/egress rates](https://www.backblaze.com/cloud-storage/transaction-pricing) · [restic B2 note](https://restic.readthedocs.io/en/stable/030_preparing_a_new_repo.html#backblaze-b2)
- **OCI:** paid accounts retain 10 GB Standard, 10 GB Infrequent Access, and 10 GB Archive allowances plus 50,000 Object Storage requests/month. For Standard-only storage beyond its free 10 GB, Oracle’s published general US-dollar list is $0.0255/GB-month; request overage $0.0034/10,000. North America/Europe outbound Internet transfer first 10 TB/month is free. Thus 10/100 GB restores incur no egress fee under that allowance; Standard storage restore adds no retrieval charge. Free-only tenancy mode is capped at 20 GiB combined, so cannot store 25 GB without upgrading. [OCI free tier](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm) · [OCI general pricing FAQ](https://www.oracle.com/cloud/storage/archive-storage/faq/)
- **R2:** egress free; Standard has no read/retrieval fee, no minimum duration, and free tier covers 1M writes / 10M reads monthly. Above the free allowance: $4.50/million Class A, $0.36/million Class B. R2 Infrequent Access is a poor fit for a live repository: $0.01/GB retrieval, $9/million writes, $0.90/million reads, 30-day minimum. [R2 pricing](https://developers.cloudflare.com/r2/pricing/)
- **AWS:** S3 Standard typical listed Canada rates: $0.0055/1,000 PUT/COPY/POST/LIST, $0.00044/1,000 GET; eligible AWS Free Tier includes 100 GB/month Internet egress aggregated across services/regions; other account egress may consume it. Deep Archive bulk retrieval is $0.005/GiB and standard retrieval $0.022/GiB in Canada Central: restoring 10/100 decimal GB is ~$0.05/$0.47 bulk or $0.20/$2.05 standard, before request fees and temporary Standard staging. Standard retrieval typically 12 hours; bulk up to 48 hours. Deep Archive objects require restore before read and 180-day minimum; short-lived daily generations can create early-delete charges. Small objects are costly in archival classes: 40 KB metadata overhead/object; Glacier Instant Retrieval also bills a 128 KB minimum object. [AWS offer file](https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonS3/current/ca-central-1/index.json) · [AWS retrieval and object constraints](https://docs.aws.amazon.com/AmazonS3/latest/userguide/glacier-storage-classes.html) · [AWS 100 GB egress allowance](https://aws.amazon.com/about-aws/global-infrastructure/global-network/faqs/)
- **Google:** Archive retrieval is $0.05/GiB, plus Internet egress generally $0.12/GiB to worldwide destinations excluding Asia/Australia. Approximate total for 10/100 decimal GB recovery from Archive: $1.58/$15.83 (decimal GB converted to GiB; operations extra). Free-tier storage/egress quotas apply only in three US regions; not Montreal/Toronto. Nearline/Coldline/Archive minimum durations are 30/90/365 days; noncurrent object versions are charged same as live objects. [GCS pricing](https://cloud.google.com/storage/pricing)
- **Azure:** cool/cold/archive storage access incurs per-GB retrieval in addition to requests. Canada Central LRS API retrieval rates: Archive $0.02/GiB; Cool $0.01/GiB, Cold $0.03/GiB. First 100 GB/month Internet egress free across Azure. Thus Archive retrieval for 10/100 decimal GB is about $0.19/$1.86 before reads/rehydration and assuming no other retrieval. Archive needs rehydration (up to 15 hours); cool/cold/archive have 30/90/180-day minimums on GPv2 accounts. [Azure Blob pricing](https://azure.microsoft.com/en-us/pricing/details/storage/blobs/) · [Azure bandwidth pricing](https://azure.microsoft.com/en-us/pricing/details/bandwidth/) · [Azure tier behavior](https://learn.microsoft.com/en-us/azure/storage/blobs/access-tiers-overview)

Archive storage prices are genuinely lower, but cold tiers are a poor default for a **live, mutable restic repository**: repository maintenance and restores need objects available; archive adds delayed rehydration, read charges, minimum-duration exposure on churn, and per-object overhead. If archive economics become important, design a separate cadence of closed, encrypted, immutable full exports (e.g. a database dump plus attachments), then tier those exports; do not blindly lifecycle-transition live restic repository objects. Treat the hot restic repository as the usable operational copy.

## Encryption, immutability, and cost guardrails

Restic encrypts/authenticates repository contents client-side; its password is essential and must be retained offsite. Encryption protects confidentiality and integrity, not deletion. Keep the cloud write key scoped to one bucket/prefix and separate destructive retention/admin credentials where feasible. A nightly job with normal restic pruning needs delete/overwrite operations; verify provider object-lock behavior against the actual backup lifecycle before locking a live repository. S3 Object Lock protects versions and has Governance/Compliance modes; R2 bucket locks prevent overwrite/delete while locked; B2 supports Object Lock. [restic repository/password docs](https://restic.readthedocs.io/en/stable/030_preparing_a_new_repo.html) · [S3 Object Lock](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock.html) · [R2 bucket locks](https://developers.cloudflare.com/r2/buckets/bucket-locks/) · [B2 Object Lock](https://www.backblaze.com/docs/en/cloud-storage-object-lock) · [B2 security](https://www.backblaze.com/docs/cloud-storage-security)

B2 lets the owner set daily caps and 75%/100% alerts; cap changes may take up to 10 minutes, and Class D is not capped, so this is not a hard monthly spend ceiling. Cloudflare account-wide budget alerts notify but do not stop products; R2 is excluded from the listed Workers/Durable Objects spending limits. [Cloudflare spend controls](https://developers.cloudflare.com/billing/manage/spend-management/). Use provider alerts plus a local size/retention alarm. AWS budgets alert but do not stop spend. Avoid assuming free-tier signup credits represent recurring prices. [B2 caps/alerts](https://www.backblaze.com/docs/en/cloud-storage-data-caps-and-alerts) · [R2 billing](https://developers.cloudflare.com/r2/pricing/) · [AWS Budgets](https://docs.aws.amazon.com/cost-management/latest/userguide/budgets-managing-costs.html)
